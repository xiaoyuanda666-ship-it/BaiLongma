# 一次性行为提醒

运行时对“可能重复、低效、没有新依据、与当前计划不一致”的判断只提供一次拦截和提醒。提醒应包含之前的实际结果，明确本次未执行。agent 在收到工具结果后仍选择相同操作时，继续执行，不再被其他判断性规则重复阻断。

## 协议与范围

- `src/runtime/behavior-reminders.js` 为每次 `callLLM` 创建共享记录。工具名及规范化参数共同标识操作；消息同时区分收件人、渠道、文字/语音和内容。不同任务回合不继承放行状态。
- 首次提醒返回 `ok: true, advisory: true, executed: false, delivered: false, message_sent: false`，以及 `reason`、`evidence`、`guidance`。`ok` 只表示提醒协议正常返回，不表示操作成功。之前的成功状态位于 `evidence`，不能冒充本次送达。
- 工具结果加入实际模型协议历史后，下一次执行请求才标记为已观察提醒。同一批预先生成的多次调用复用同一提醒，不能互相充当确认。无需 agent 输出特定口令或申请用户批准。
- 同一操作在下一次执行响应里再次出现，所有判断性规则共享放行记录。出现新规则也不能叠加第二次提醒。新的参数、收件人或任务回合有独立记录。
- 提醒不计入连续失败，不作为新的成功工具证据，也不触发整批停止。UI 显示“已提醒”，而不是“成功”或“失败”。

## 已接入的判断

| 位置 | 行为 |
| --- | --- |
| 模型工具循环 | 相同失败重试、重复工具循环、推断出的任务范围和顺序、尚缺完成证据、计划检查建议完成或停止 |
| 消息发送 | 相同消息已送达、同一心跳无新证据、同批次后续发送、客套收尾、播放后的多余确认 |
| 投递层 | 最近成功投递、未获回复的历史投递、之前的外部投递失败 |
| 记忆写入 | 模仿或复述被判断为不适合存成用户事实 |
| 心跳设置 | 重复设置当前间隔；提醒后可以有意重新续期 |

语音合成位于投递检查之后；被提醒拦截的调用不生成音频。相同内容的文字和语音可以分别投递。曾失败的发送不会被表示成成功。

实际权限、显式工具禁用、内部静默信号的通信权限、浏览器挑战边界、参数及真实工具前置条件、仍在执行中的投递锁，以及回合资源预算继续校验。提醒后的再次决定不能改变这些条件。进行中的投递没有成功结果，不使用“已经送达”的提醒。

## 验证

运行 `src/test-behavior-reminders.js`，覆盖 Responses 与 Chat Completions 的实际工具历史、提醒后的真实投递和语音合成、同批调用、跨层放行、失败恢复、非消息工具、记忆写入及心跳续期。相关表达、计划检查、权限、浏览器边界和投递测试同时保留。

当前依赖的 SQLite 原生模块按 Electron ABI 编译，可以用：

```sh
ELECTRON_RUN_AS_NODE=1 ./node_modules/.bin/electron src/test-behavior-reminders.js
```

测试使用临时数据目录、模拟模型与语音合成，不发送外部消息，也不调用付费模型。
